Building a consent-gated URLhaus adapter

Implementation notes, validation, and lessons from upstream contributions.

The goal of PR #133 was to add an optional, read-only URLhaus threat-intelligence lookup without turning network requests into an implicit side effect. The integration uses explicit consent and bounded, fail-closed behavior.

Implementation and tests

I implemented the adapter and mocked tests for normal responses, error handling, and consent. The maintainer reviewed the contribution and prepared companion PR #136, adding stricter record-ID validation, calendar-valid timestamps, and rejection of contradictory no-results responses.

Independent review

I reviewed the companion changes, ran 29 URLhaus tests and eight threat-intelligence test programs locally, and checked that new tests detected the original edge cases. I raised a small consistency question about the string "0" versus numeric 0 as a record ID. The maintainer also reported passing security CI and six GitHub workflows.

What remains

Both changes remain subject to maintainer integration decisions. The evaluation used offline, mocked responses; it did not establish live API compatibility, production readiness, or Windows DPAPI persistence behavior. Original PR · Companion PR.
