GUARDIAN PROTOCOL · PR #182 · AI AGENT SECURITY

Give GP-0002 a distinct exfiltration scenario

MERGED

Problem

Two AI-agent attack patterns were effectively exercising the same experiment, which weakened the distinction between the scenarios and their security coverage.

Change

The contribution gives GP-0002 its own seeded customer-record exfiltration path through an HTTP tool, with a separate canary, precondition, judge, evidence text, hardened control path, and regression coverage that keeps the scenarios distinct.

What I learned

Security tests need to prove distinct behaviors, not just carry different labels. Separating the attack chain and expected evidence makes the coverage more meaningful and easier to validate.

GOMBIT · PR #613 · AUTHENTICATION

Return the right Bearer challenge on handler 401s

MERGED

Problem

Some session-revocation routes could return a handler-generated 401 without the WWW-Authenticate Bearer challenge expected by clients using Bearer authentication.

Change

The fix adds the Bearer challenge to those 401 responses while leaving cookie-mode responses and non-401 errors unchanged, with focused regression coverage around the boundary.

What I learned

Authentication behavior is more than accepting or rejecting credentials. HTTP challenge semantics are part of the contract clients depend on, and fixes should avoid changing unrelated auth modes.

AUTENTICO · PR #490 · SECURITY

Keep query-string secrets out of request logs

MERGED

Problem

Logging a full request URL can copy reset tokens, magic-link tokens, authorization codes, and PKCE verifiers into access logs.

Change

The logger records the request path without the query string. Regression coverage verifies that useful path information remains while sensitive parameter values do not appear.

What I learned

A secret can be protected in the application and still leak through observability. Logging boundaries are part of the security boundary.
