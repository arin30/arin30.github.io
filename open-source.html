GOMBIT · PR #613 · AUTHENTICATION

Return the correct Bearer challenge on handler 401s

UNDER REVIEW

Problem

Bearer-protected session-revocation routes could return a handler-generated 401 without the HTTP authentication challenge expected by Bearer clients.

Change

The contribution adds WWW-Authenticate: Bearer realm="api" to those Bearer-mode 401 responses while leaving cookie authentication and non-401 errors unchanged, with focused regression coverage.

What I learned

Authentication behavior is more than status codes. HTTP clients rely on challenge headers to understand which authentication scheme a protected resource expects.

GOMBIT · PR #614 · API CONTRACT

Document the verification resend rate limit

UNDER REVIEW

Problem

The verification resend endpoint already returned HTTP 429 at runtime, but its OpenAPI contract did not describe that response or its Retry-After header.

Change

The contribution declares the 429 response, requires an integer Retry-After value of at least one second, preserves the default error response, tests Bearer and cookie modes, and updates generated TypeScript contracts.

What I learned

An API can behave correctly at runtime and still have a broken contract. Generated clients and integrators need the specification to match the responses the server actually sends.

AUTENTICO · PR #490 · SECURITY

Keep query-string secrets out of request logs

UNDER REVIEW

Problem

Logging a full request URL can copy reset tokens, magic-link tokens, authorization codes, and PKCE verifiers into access logs.

Change

The logger records the request path without the query string. Regression coverage verifies that useful path information remains while sensitive parameter values do not appear.

What I learned

A secret can be protected in the application and still leak through observability. Logging boundaries are part of the security boundary.

Change
