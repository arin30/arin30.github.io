How SignalF0rge turns raw events into a security finding

The short version: parse the telemetry, evaluate individual events, connect related behavior, then give the analyst the evidence—not just an alert name.

← ALL WRITEUPS
SEPTEMBER 2026 · ARIN AERUVA · 7 MIN READ

SignalF0rge started with a simple question: if I had a stream of authentication, endpoint, and network events, what would I need to turn them into something an analyst could actually investigate?

Matching one suspicious event is useful, but it is also the easy part. The more interesting problem is recognizing that several events belong to the same story.

1. Normalize before detecting

Different telemetry sources describe the same ideas in different ways. A user may be called user, username, or account_name. SignalF0rge converts incoming JSONL events into a consistent shape so the detection logic does not need to understand every source format.

raw event → normalize fields → evaluate rule → preserve evidence

That keeps every rule from turning into a pile of source-specific exceptions.

2. Treat a rule match as evidence

The rule engine checks normalized events for behaviors such as password spraying, suspicious PowerShell, LSASS access, shadow-copy deletion, and a successful authentication after repeated failures.

A rule match is evidence. It is not automatically a complete incident.

Each match keeps the event details, severity, entity, time window, and MITRE ATT&CK technique attached. That makes the report explainable later.

3. Correlate behavior across time and entities

This is the part I care about most. SignalF0rge groups events around shared users, hosts, source IPs, and time windows. It can recognize a sequence such as repeated authentication failures, a successful login, encoded PowerShell, credential access, and a high-risk outbound connection.

failed logins → successful login → PowerShell → LSASS access → outbound connection

result: one multi-stage finding, not five disconnected alerts

The goal is not to hide the alerts. It is to give them context while keeping the individual evidence visible.

4. Score and report the finding

The engine prioritizes the resulting findings and generates an HTML report. A Windows Sysmon sample currently produces 32 findings, including higher-confidence behavioral chains such as a multi-stage account compromise pattern.

What I’m working on next

I want to improve the realism of the datasets and evaluate false positives more deliberately. A detector that fires often can look impressive in a demo. A detector that gives an analyst a smaller amount of strong, explainable evidence is much more useful.
